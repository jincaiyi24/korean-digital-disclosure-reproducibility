## 왜 규칙 기반 문장분류를 사용하는가

이 연구는 기업의 디지털 공시가 어떤 방향을 담고 있는지를 측정합니다. 같은 디지털 기술어가 등장해도 기술 소개, 외부 시장 동향, 해당 기업의 구체적 활동은 연구상 의미가 다릅니다. 고객·서비스·채널·거래·수익과 연결된 공시를 구분하여 BMODD와 후속 경영효율의 관계를 살펴봅니다.

Python 분류는 이 개념 구분을 현재 잠금자료의 25,041,971개 문장 단위에 같은 절차로 적용하고, 기업명·보고연도에 관한 조건을 반영하여 기업연도별 공시비율로 집계하기 위한 구현입니다.

디지털 관련성 C, 기업 활동의 구체성과 실질성 S, 사업모델 연결 B를 구분해 기록합니다. NonBMODD는 S=1인 문장 중 BMODD 규칙에 해당하지 않는 잔여범주이며, 모두 내부 시스템이나 기술 인프라 활동이라는 뜻은 아닙니다. 후보 여부만으로 유효 문장을 사전 제외하지 않습니다.

어휘, 문맥 조건, 제외 규칙과 적용 순서를 공개하여 독자가 원문과 코드를 대조할 수 있도록 합니다. Python은 이를 일관되게 실행하는 도구이며, 코드북의 개념적 판단은 어휘·정규표현식으로 근사합니다. 실행의 재현성과 인간 코딩에 대한 분류 성능은 구분해서 평가합니다.

## 실행환경 준비

Python 3.13.12 Windows 64비트 일반 빌드와 잠금 의존성을 사용합니다. 예시는 PowerShell입니다.

```powershell
py -3.13 --version
py -3.13 -m venv .venv
$reproPy = ".\.venv\Scripts\python.exe"
& $reproPy -m pip install --require-hashes -r ".\코드\파이썬313_의존성_해시잠금.txt"
& $reproPy -m pip check
```

## 원문 확보 또는 기존 원문 점검

원문 ZIP과 HTML은 저장소에 포함하지 않습니다. 이미 원문이 있으면 별도 자료 디렉터리에 raw_dart, supplemental_raw, viewer_capture를 보관합니다. 다음 명령은 기존 원문을 오프라인으로 검사하며 지정한 자료 디렉터리에 파일이나 디렉터리를 추가하지 않습니다.

```powershell
& $reproPy -B ".\코드\재현실행.py" --mode acquire `
  --data-root "D:\잠금자료" --check-only
```

원문을 새로 확보하거나 모든 파일이 이미 검증된 상태에서 표준 빈 디렉터리까지 준비하려면 명시적으로 --fetch를 사용합니다. 누락된 파일만 원래 확보 도구에 위임하며, 출처와 기대 SHA가 다르면 다른 보고서로 대체하지 않고 중단합니다. 다음 키 입력 예시는 PowerShell 7용입니다.

```powershell
$env:DART_API_KEY = Read-Host "OpenDART API key" -MaskInput
& $reproPy -B ".\코드\재현실행.py" --mode acquire `
  --data-root "D:\잠금자료" --fetch
[Environment]::SetEnvironmentVariable("DART_API_KEY", $null, "Process")
```

--mode acquire는 --data-root와 --check-only 또는 --fetch만 받습니다. 기본값은 --check-only이며 출력 폴더나 회귀 실행 인자는 받지 않습니다. 사이트의 현재 응답이 과거 잠금 바이트와 다르면 확보에 실패할 수 있습니다. 이번 기존 세 차례 재현에서는 새 웹·재무 다운로드를 수행하지 않았습니다.

## 입력 점검과 실제 계산

기본 재현 모드는 원래 진입점의 오프라인 입력 점검입니다. 반드시 존재하지 않는 새 출력 폴더를 지정합니다.

```powershell
& $reproPy -B ".\코드\재현실행.py" `
  --data-root "D:\잠금자료" --output "D:\재현결과\입력점검01"
```

실제 세 차례 계산은 별도의 새 출력 경로에 --run을 지정합니다.

```powershell
& $reproPy -B ".\코드\재현실행.py" `
  --data-root "D:\잠금자료" --output "D:\재현결과\새실행01" `
  --run --rounds 3
```

자료 경로가 분리되어 있으면 --raw-dir, --supplemental-raw-dir, --viewer-capture-root를 함께 지정합니다. --finance-root는 기존 원래 파일명을 가진 외부 재무 입력 폴더를 쓸 때만 지정하며 기본값은 동봉한 안전 사본입니다. 상대 경로는 호출한 현재 디렉터리를 기준으로 절대 경로로 바꾸어 전달합니다. --bundle은 외부에서 바꾸지 않고 검증된 복원본으로 고정합니다.

## 한글 파일명과 원래 실행 경로

`코드/파일명대응표.json`은 현재 보존된 94개 파일의 원래 경로, 한글 경로, 크기와 SHA-256을 연결합니다. `재현실행.py`는 모든 파일을 검사한 뒤 독립 임시 공간에 원래 94개 경로와 바이트를 복원하고 수정하지 않은 원래 public_run.py 또는 acquire_locked_reports.py에 위임합니다. 원래 import 이름·분류 규칙·입력·모형·수치 결과를 바꾸지 않습니다. 작업이 끝나면 이 진입점이 만든 임시 복원 공간만 정리하며 사용자 원문과 출력은 보존합니다.

`원본_` 파일은 원본 보존용입니다. 개별 파일을 직접 실행하지 말고 `재현실행.py`를 사용합니다. 규칙 목록에 남아 있는 영문 소스 경로는 복원된 실행 트리의 논리 경로이며 대응표에서 한글 파일명을 찾을 수 있습니다. 기존 안내 보존본은 [기존 실행안내](설명서/기존_실행안내.md)입니다.
